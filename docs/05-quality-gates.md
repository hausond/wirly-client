# Гейты качества

Статус: **действует**. Обход гейта — инцидент, а не «ускорились».

## 1. Уровни гейтов

| Уровень | Когда | Цель |
|---|---|---|
| L0 pre-commit | перед коммитом | не пускать мусор в историю |
| L1 pre-push | перед пушем | быстрые проверки локально |
| L2 CI (PR) | на каждый PR | полный набор, блокирует merge |
| L3 merge | при слиянии | защита `main` |
| L4 release | при теге | артефакты и подпись |

## 2. L0: pre-commit

Обязательно:

- `cargo fmt --all -- --check` (или автоформат);
- запрет на коммит файлов > 5 МБ и бинарников без LFS;
- запрет на секреты (regex-сканер + `gitleaks` при наличии);
- запрет на `dbg!`, `println!` в библиотеках, `TODO` без owner/issue.

## 3. L1: pre-push

Быстрый прогон (< 3 минут):

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Хук лежит в `.githooks/pre-push`; включается `scripts/setup-hooks.ps1`.
Хук **нельзя** обходить (`--no-verify` запрещён регламентом).

## 4. L2: CI на PR

Обязательные джобы (все блокирующие):

| Джоба | Команда | Порог |
|---|---|---|
| `fmt` | `cargo fmt --all -- --check` | 0 диффов |
| `clippy` | `cargo clippy --workspace --all-targets -- -D warnings` | 0 warning |
| `test` | `cargo test --workspace --all-features` | 0 падений |
| `coverage` | `cargo llvm-cov -p <crate> --fail-under-lines 100` для каждого крейта | 100% строк |
| `docs` | `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps` | 0 warning |
| `deny` | `cargo deny check` | 0 нарушений |
| `audit` | `cargo audit` | 0 уязвимостей (кроме allow-list с сроком) |
| `msrv` | сборка на MSRV из `Cargo.toml` | успех |
| `lockfile` | `git diff --exit-code Cargo.lock` после сборки | lock актуален |

Дополнительно (предупреждающие, не блокируют merge, но обязательны к фиксу
в течение недели): `cargo-mutants`, `cargo-fuzz` smoke, бенчмарки.

## 5. Покрытие

- `crates/**` — 100% строк.
- Изменённые строки в PR — 100% (patch coverage).
- Бинарники исключены из подсчёта, но покрыты интеграционными тестами.
- Гейт выполняется **по каждому крейту отдельно**
  (`cargo llvm-cov -p <crate> --fail-under-lines 100`): это исключает
  кросс-крейтовые артефакты мульти-инстанцирования. `vpn-ipc` не содержит
  исполняемых строк и в цикл не входит.
- Исключения — только по [правилам](03-testing.md#6-исключения-из-покрытия).
- Локально на gnu-тулчейне coverage не инструментируется — гейт выполняет CI (MSVC);
  `scripts/check.ps1` в этом случае показывает `SKIP` с пояснением.

## 6. Безопасность зависимостей

`cargo-deny` проверяет:

- **advisories** — уязвимости;
- **licenses** — только разрешённый список (`deny.toml`);
- **bans** — запрещённые крейты (дубли, GPL, заброшенные);
- **sources** — только crates.io (без git-зависимостей без ADR).

Правило: уязвимость с CVSS ≥ 7 — блокер. Исключение оформляется ADR с
обоснованием, сроком и компенсирующей мерой.

## 7. Документация

- `cargo doc` без предупреждений.
- Изменение поведения без правки доков = красный ревью-чек.
- Битая ссылка в `docs/` — дефект (проверяется `lychee` в ночном прогоне).

## 8. Производительность

- Бенчмарки `criterion` для горячих путей (`routing::decide`, парсеры).
- Регрессия > 10% относительно `main` — блокер релиза (не PR).
- Результаты публикуются в PR как артефакт.

## 9. Флейки

- Флейк = инцидент. В течение 24 часов: исправить или удалить тест с issue.
- Повторный запуск CI для «позеленения» запрещён.
- Ветка с флейком не мержится.

## 10. Обход гейтов

Не существует «кнопки обойти». Единственный путь:

1. инцидент уровня P0 (недоступность/утечка);
2. ветка `hotfix/<id>`;
3. два ревьюера, один — техлид;
4. явное исключение в PR с обоснованием и сроком;
5. post-mortem в течение 48 часов.

Любой `#[allow]`, `--no-verify`, отключение теста или правка CI-порога без
этого процесса — нарушение регламента.

## 11. Локальная проверка «как в CI»

```powershell
scripts/check.ps1
```

Скрипт последовательно запускает все L1/L2-проверки, доступные локально,
и печатает итоговую таблицу. Ненулевой код возврата = нельзя пушить.
