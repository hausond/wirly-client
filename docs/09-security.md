# Безопасность

Статус: **действует**. Изменения в этом документе — только с ревью security.

## 1. Модель угроз

| Угроза | Вектор | Защита |
|---|---|---|
| Локальный непривилегированный процесс | подмена IPC, кража ключей | ACL на канале, секреты только в службе |
| Вредоносный сервер | MITM, подмена сертификата | TLS-проверка, REALITY-верификация, pinning для обновлений |
| Сетевой наблюдатель | DPI, корреляция | обфускация, минимум метаданных |
| Компрометация зависимости | supply chain | lockfile, `cargo-deny`, аудит, минимальный набор крейтов |
| Компрометация обновления | подмена бинарника | подпись релиза, проверка хеша |
| Утечка при обрыве | трафик уходит напрямую | kill switch, DNS-leak protection |
| Ошибка в crypto-коде | уязвимость | только проверенные крейты, без «своей крипты» |

## 2. Привилегии

- Служба работает под `LocalSystem`, но с минимально необходимым набором прав.
- UI — обычный пользователь, без elevation.
- IPC: named pipe с DACL, разрешающим только текущего пользователя и SYSTEM.
- Служба валидирует **каждое** сообщение: размер, схему, допустимость операции.
- UI не может запросить произвольный путь к файлу/ключу.

## 3. Секреты

- Хранение: DPAPI (`CryptProtectData`) в области службы; файлы с ACL `SYSTEM`+`Administrators`.
- В памяти: минимизировать время жизни, по возможности zeroize.
- В логах: запрещены; `Debug` для конфигов с секретами реализуется вручную.
- В репозитории: запрещены; проверка `gitleaks` в pre-commit и CI.
- При утечке — немедленная ротация ключа и запись инцидента.

## 4. Kill switch

- При падении/обрыве трафик блокируется WFP-фильтрами.
- Разрешены только: интерфейс службы, DNS к локальному резолверу (если настроено),
  loopback.
- Тесты: имитация падения службы, обрыва туннеля, смены сети (Wi-Fi → Ethernet).
- Kill switch **не** должен блокировать управляющий канал службы.

## 5. DNS

- По умолчанию DNS идёт через туннель (fake-IP).
- Запрещены «утечки» через системный резолвер: запросы к внешним DNS
  блокируются или перенаправляются.
- DoH/DoT — только к разрешённым серверам из конфига.
- Тест: запрос к `whoami.akamai.net` не должен уходить в обход туннеля.

## 6. Криптография

- Запрещено реализовывать примитивы самостоятельно.
- Допустимые источники: `ring`, `rustls`, `boring`, `x25519-dalek`, `chacha20poly1305`
  (после проверки лицензии и аудита).
- Случайность — только `OsRng`/`getrandom`.
- Сравнение секретов — constant-time.
- Любое изменение крипто-слоя — ADR + security-ревью.

## 7. Supply chain

- `Cargo.lock` обязателен, обновление — отдельным PR.
- `cargo-deny`: advisories, licenses, bans, sources.
- Git-зависимости запрещены без ADR.
- Запрещены крейты без поддержки (> 2 лет без коммитов) — исключение через ADR.
- Релизные артефакты подписываются; хеши публикуются.

## 8. Раскрытие уязвимостей

- Контакт: security@<домен проекта> (заполнить при регистрации домена).
- Срок реакции: 72 часа; исправление критичных — 14 дней.
- Публичное раскрытие — после исправления и согласования.
- Инциденты фиксируются в `docs/incidents/NNNN-<slug>.md`.

## 9. Чек-лист security-ревью PR

- [ ] нет новых секретов/логов с приватными данными;
- [ ] IPC-сообщения валидируются;
- [ ] нет `unsafe` без ADR;
- [ ] нет новых крипто-зависимостей без обоснования;
- [ ] не ослаблены проверки TLS/REALITY;
- [ ] kill switch не обходится;
- [ ] нет сетевых утечек при ошибках.
