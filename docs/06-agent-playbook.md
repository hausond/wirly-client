# Playbook для AI-агентов

Статус: **обязателен к исполнению**. Это контракт, а не рекомендация.
Нарушение любого пункта — основание отклонить PR целиком.

## 0. Кто ты

Ты — исполнитель в проекте `hausond vpn`. Твоя задача — вносить изменения,
которые проходят ревью с первого раза и не создают долга. Скорость вторична.
Ты не принимаешь продуктовых решений и не расширяешь рамки без явного указания.

## 1. Обязательное чтение перед первым действием

В этом порядке:

1. `docs/00-charter.md`
2. `docs/01-architecture.md`
3. `docs/02-code-standards.md`
4. `docs/03-testing.md`
5. `docs/04-git-and-review.md`
6. `docs/05-quality-gates.md`
7. `docs/13-definition-of-done.md`
8. Спецификация области, которую трогаешь (`07`–`12`).

Если задача противоречит этим документам — **остановись** и задай вопрос.
Не «делай как проще».

## 2. Жёсткие запреты (без исключений)

- ❌ Прямой пуш в `main`, force-push, `--no-verify`.
- ❌ Правка `.github/**` или порогов CI, чтобы «позеленить».
- ❌ Удаление, отключение (`#[ignore]`) или ослабление тестов.
- ❌ `#[allow(...)]` без `WHY:`-комментария и ссылки на issue.
- ❌ `unwrap`/`expect`/`panic!` в библиотечном коде.
- ❌ Новые зависимости без обоснования и проверки лицензии.
- ❌ GPL/AGPL-код, портирование из `sing-box`/`mihomo`.
- ❌ Секреты, ключи, реальные IP/пароли в коде, тестах, логах, коммитах.
- ❌ Изменение публичного API без semver-обоснования.
- ❌ Смешивание рефакторинга и поведения в одном PR.
- ❌ Выдумывание требований, если в задаче есть пробел.

## 3. Рабочий цикл

1. **Прочитай задачу и найди её в issue.** Нет issue — попроси создать.
2. **Составь план** (3–7 пунктов) и приложи его к PR-описанию.
3. **Создай ветку** по [правилам](04-git-and-review.md#1-модель-ветвления).
4. **Пиши тест раньше или вместе с кодом.** Без теста изменение не существует.
5. **Реализуй минимально достаточное решение.** Без «на будущее».
6. **Обнови документацию**, если поведение/API/формат изменились.
7. **Прогони локальные гейты** (`scripts/check.ps1`).
8. **Сделай PR** по шаблону; опиши риски и способ проверки.
9. **Отвечай на ревью**; каждый комментарий — resolve или аргумент.
10. **Дождись зелёного CI.** Merge делает человек или CI-бот по политике.

## 4. Границы изменений

| Что | Можно | Нельзя |
|---|---|---|
| `crates/vpn-config` | парсеры, типы профилей | сеть, TUN, роутинг |
| `crates/vpn-routing` | правила, матчеры, пресеты | протоколы, сокеты |
| `crates/vpn-dns` | fake-IP, резолвер | маршруты, TUN |
| `crates/vpn-proto` | реализации `Outbound` | UI, маршруты |
| `crates/vpn-tun` | платформенный код | бизнес-логика роутинга |
| `crates/vpn-core` | оркестрация сессии | платформенные API напрямую |
| `crates/vpn-ipc` | сообщения | бизнес-логика |
| `apps/**` | сборка зависимостей, wiring | дублирование логики крейтов |

Правило: если для задачи нужен код «не в своём» крейте — сначала предложи
изменение архитектуры через ADR.

## 5. Неоднозначность

Останавливайся и спрашивай, если:

- требование допускает два разных поведения;
- нужно менять публичный API или формат данных;
- задача требует новой зависимости или `unsafe`;
- непонятно, к какому крейту относится логика;
- предложенное решение конфликтует с документацией;
- тест невозможно сделать детерминированным.

Формат вопроса: контекст → варианты → рекомендация → последствия.

## 6. Definition of Done (сокращённая версия)

Изменение готово, только если:

- [ ] поведение соответствует задаче и уставу;
- [ ] есть тесты, покрытие 100% (в т.ч. граничные случаи и ошибки);
- [ ] `cargo fmt`, `clippy -D warnings`, `test`, `coverage`, `deny` — зелёные;
- [ ] публичный API документирован;
- [ ] документация обновлена;
- [ ] нет `unsafe`, `unwrap`, секретов, `#[allow]` без причины;
- [ ] нет новых зависимостей без обоснования;
- [ ] PR ≤ 400 строк, один логический смысл;
- [ ] все комментарии ревью закрыты.

Полная версия — `docs/13-definition-of-done.md`.

## 7. Формат PR-описания

```markdown
## What
<одно-два предложения>

## Why
<ссылка на issue, причина>

## How tested
<команды + ручные сценарии>

## Risks
<влияние на безопасность/производительность/совместимость; "none" если нет>

## Docs
<какие файлы обновлены или "not needed: причина">

## Checklist
- [ ] tests added/updated
- [ ] coverage 100%
- [ ] docs updated
- [ ] no new deps / deps justified
```

## 9. Эскалация

Эскалируй немедленно, если:

- обнаружена уязвимость или утечка секрета;
- тест нестабилен и не лечится за 30 минут;
- требуется обойти гейт;
- задача затрагивает `docs/09-security.md` или `.github/**`;
- найден конфликт требований.

Эскалация = сообщение с меткой `[BLOCKED]`, описанием и предложенным планом.

## 10. Антипаттерны

- «Потом добавим тесты».
- «CI всё равно медленный, отключу».
- «Сделаю `#[allow]`, потом разберусь».
- «Добавлю зависимость, она удобная».
- «Перепишу весь файл, так проще».
- «Обойду проверку, чтобы успеть».
- «Скопирую код из sing-box» (лицензия).
- «Сделаю как в mihomo» (лицензия + архитектура).

## 11. Самопроверка перед пушем

Ответь себе честно:

1. Я покрыл тестами **все** ветки, включая ошибки?
2. Если я удалю свой код, тест упадёт?
3. Есть ли место, где ошибка глотается?
4. Не логирую ли я секреты/IP?
5. Не нарушил ли я границы крейтов?
6. Сможет ли другой человек понять изменение без меня?
7. Обновил ли я документацию?

Если хоть один ответ «нет» — не пушь.
