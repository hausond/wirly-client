# Контракт протоколов

Статус: **действует**. Реализация протокола без соблюдения контракта не принимается.

## 1. Trait `Outbound`

```rust
#[async_trait]
pub trait Outbound: Send + Sync {
    fn name(&self) -> &str;
    async fn dial_tcp(&self, target: &Target) -> Result<TcpStream, ProtoError>;
    async fn dial_udp(&self, target: &Target) -> Result<UdpSocket, ProtoError>;
}
```

Обязанности реализации:

- вернуть **готовый** поток/сокет, по которому можно сразу передавать данные;
- не выполнять DNS-резолв, если передан домен: резолв — часть протокола
  (сервер должен видеть домен, если это поддерживается);
- уважать переданный `Target { host, port }` (host может быть доменом или IP);
- соблюдать таймаут подключения (≤ 10 с по умолчанию);
- корректно освобождать ресурсы при отмене future;
- не паниковать и не логировать секреты.

## 2. Жизненный цикл

```
create(profile) -> Box<dyn Outbound>
  -> dial_tcp/dial_udp (много раз, параллельно)
  -> drop (закрытие всех ресурсов)
```

- `create` валидирует конфиг; при ошибке — `ProtoError::Config` с понятным текстом.
- Один экземпляр `Outbound` обслуживает много соединений конкурентно.
- Внутреннее состояние — потокобезопасное; без блокирующих мьютексов на горячем пути.

## 3. Ошибки

```rust
pub enum ProtoError {
    NotImplemented(&'static str),
    Config(String),
    Io(std::io::Error),
    Auth,            // сервер отверг ключ/пароль
    Timeout,
    Protocol(String),// нарушение протокола
}
```

Правила:

- `NotImplemented` — только для заглушек, никогда в релизе;
- `Io` сохраняет исходную ошибку (не терять `ErrorKind`);
- ошибки не содержат ключей, паролей и полного содержимого пакетов.

## 4. UDP

- Если протокол не поддерживает UDP, `dial_udp` возвращает
  `ProtoError::NotImplemented("udp")`, а клиент должен показать это в UI.
- Для QUIC/Hysteria2 UDP — основной транспорт.
- `dial_udp` возвращает сокет, привязанный к туннелю, а не к системному интерфейсу.

## 6. Требования к каждому протоколу

1. **Конфиг** — сериализуемый тип в `vpn-config`, без секретов в `Debug`.
2. **Парсинг share-ссылки** — в `vpn-config::parse_uri`, с тестами.
3. **Контракт** — реализация `Outbound` в `vpn-proto`.
4. **Тесты**:
   - unit: разбор конфига, векторы заголовков;
   - integration: соединение с эталонным сервером (в тестовом окружении);
   - negative: неверный ключ/пароль → `Auth`, таймаут → `Timeout`.
5. **Документация** — раздел в этом файле + пример конфига.
6. **Ограничения** — явно описаны (UDP, flow, TLS-версии, ALPN).

## 7. REALITY: особые требования

- Использовать только проверенную реализацию TLS-стека (BoringSSL через `boring`).
- ClientHello должен соответствовать выбранному отпечатку; отпечаток — параметр конфига.
- Запрещено «упрощать» REALITY самостоятельно: только спецификация + interop-тесты
  против Xray.
- Тест-векторы: успешный handshake, неверный public key, неверный shortId,
  несовпадение SNI.
- Любое изменение — ревью security + ADR.

## 8. Лицензионная гигиена

- Код протоколов пишется самостоятельно либо берётся из разрешённых лицензий.
- Порты/адаптации GPL-кода запрещены (см. `deny.toml`).
- При сомнении — вопрос техлиду до начала работы.

## 9. Как тестируется

- **Unit**: парсинг, сериализация, генерация заголовков.
- **Golden vectors**: фиксированные байты для handshake/заголовков.
- **Interop**: Docker-контейнер с эталонным сервером (Xray/sing-box/wg) в ночном прогоне.
- **Chaos**: обрыв соединения, потеря пакетов, смена MTU.
- **E2E**: реальный сервер, проверка `api.ipify.org` и заблокированного ресурса.

- Добавлять протокол без записи в матрице и тестов.
- Возвращать «сырой» `TcpStream` до завершения handshake.
- Игнорировать `Target.host` в пользу локального DNS без явной причины.
- Хардкодить таймауты/порты в реализации без константы и документации.
