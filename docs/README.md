# Документация проекта

Этот каталог — **единственный источник истины** по процессам, архитектуре и стандартам
проекта. Если код расходится с документацией — это дефект, а не «так исторически сложилось».

## Для кого

- люди (разработчики, ревьюеры, релиз-менеджер);
- AI-агенты, которые вносят изменения в код.

Для агентов обязателен [playbook](06-agent-playbook.md) — это контракт, а не рекомендация.

## Приоритет документов

При конфликте действует следующий порядок (сверху — сильнее):

1. `docs/00-charter.md`
2. `docs/adr/*` (принятые решения)
3. `docs/07-routing-spec.md`, `docs/08-protocols.md`, `docs/09-security.md` (спецификации)
4. `docs/02-code-standards.md`, `docs/03-testing.md`, `docs/04-git-and-review.md`,
   `docs/05-quality-gates.md` (регламенты)
5. `docs/06-agent-playbook.md`, `docs/13-definition-of-done.md` (процедуры)
6. `README.md`, комментарии в коде

## Как менять документацию

- Любое изменение поведения = изменение документа **в том же PR**.
- Архитектурное решение оформляется как ADR в `docs/adr/NNNN-slug.md`.
- Изменение регламентов (`02`–`06`, `13`) требует ревью техлида.
- Удаление пункта из документа допустимо только с обоснованием в PR.

## Язык

Документация — русский. Идентификаторы кода, имена файлов, коммиты и PR-заголовки —
английский (Conventional Commits). Смешивать внутри одного абзаца не нужно.
