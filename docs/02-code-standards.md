# Стандарты кода

Статус: **действует**. Нарушение = красный CI. Исключения — только через
`#[allow]` с обоснованием и ссылкой на issue (см. §3).

## 1. Базовые требования

- Edition 2021, MSRV фиксирован в `Cargo.toml` (`rust-version`) и проверяется в CI.
- Форматирование — `cargo fmt --all`; ручные отступы не обсуждаются.
- Максимальная ширина строки — 100.
- Никаких предупреждений компилятора: `RUSTFLAGS="-D warnings"` в CI.
- `Cargo.lock` коммитится (это приложение, не библиотека).

## 2. Линты

В `[workspace.lints]` включены:

- `unsafe_code = "forbid"` — см. §6;
- `rust_2018_idioms`, `unused_must_use` — deny;
- `clippy::all`, `clippy::correctness`, `clippy::suspicious`, `clippy::complexity`,
  `clippy::perf` — deny;
- `clippy::pedantic` — warn (постепенно переводим в deny по фазам).

Каждый крейт обязан объявить `[lints] workspace = true`.

## 3. Политика `#[allow]`

Разрешено только в виде:

```rust
// SAFETY/WHY: <почему без этого нельзя>, <что это ограничивает>, <когда убрать>
#[allow(clippy::too_many_arguments)]
fn ...
```

Требования:

- `WHY:`-комментарий обязателен;
- ссылка на issue, если ограничение временное;
- запрещено глушить линт на уровне крейта (`#![allow(...)]`) без ADR;
- запрещено добавлять `#[allow]`, чтобы «покрасить» CI.

## 4. Именование

| Сущность | Стиль | Пример |
|---|---|---|
| Крейт | `vpn-<область>` | `vpn-routing` |
| Модуль | `snake_case`, существительное | `engine`, `fake_ip` |
| Тип/трейт | `UpperCamelCase` | `RoutingEngine`, `Outbound` |
| Функция/метод | `snake_case`, глагол | `decide`, `dial_tcp` |
| Константа | `SCREAMING_SNAKE_CASE` | `MAX_RETRIES` |
| Ошибка | `<Область>Error` | `ProtoError` |
| Тест | `given_<условие>_when_<действие>_then_<результат>` | `given_udp_when_routed_then_blocked` |

Запрещены сокращения, кроме общепринятых (`ip`, `dns`, `tcp`, `udp`, `tls`).

## 5. Ошибки

- В библиотеках — `thiserror`, типизированные ошибки, без `anyhow`.
- `anyhow` разрешён только в бинарниках (`apps/*`) и тестах.
- Ошибка должна нести контекст: что делали и с чем.
- Запрещено глотать ошибки (`let _ = ...`) без комментария `WHY:`.
- Ошибки не должны содержать секретов, ключей, паролей и полного содержимого пакетов.

## 6. `unsafe`

- `unsafe` запрещён на уровне workspace.
- Исключение оформляется ADR и локализуется в отдельном модуле с
  `#[allow(unsafe_code)]`, обёрткой safe-API и тестами.
- Каждый `unsafe`-блок обязан иметь `// SAFETY:` с инвариантами.
- FFI-вызовы Windows — только через типизированные обёртки, без «сырых» указателей
  в публичном API.

## 7. Паники

- В библиотечном коде запрещены `unwrap`, `expect`, `panic!`, `unreachable!`.
- Допустимо: `expect` в `main`/тестах, `unreachable!` после доказанного инварианта
  с комментарием.
- Индексация срезов — только после проверки длины или через `get`.
- Арифметика, которая может переполниться, — `checked_*`/`saturating_*`.

## 8. Async

- Никаких блокирующих вызовов в async (`std::fs`, `std::net`, CPU-bound) —
  только `spawn_blocking` или асинхронные аналоги.
- Каждая сетевая операция имеет таймаут; отмена должна освобождать ресурсы.
- `select!` — с обработкой всех ветвей, включая отмену.
- Не держать `Mutex` через `.await`.
- Каналы предпочтительнее разделяемого состояния.

## 9. Публичный API и документация

- Каждый `pub`-элемент имеет doc-комментарий (`///`).
- Doc-примеры должны компилироваться и запускаться в CI.
- Публичные типы реализуют `Debug`; секретные поля маскируются вручную.
- Semver: любое ломающее изменение публичного API крейта — мажорное.

## 10. Зависимости

- Новая зависимость = обоснование в PR (зачем, чем хуже альтернативы, лицензия).
- Лицензии: только MIT/Apache-2.0/BSD/ISC/Zlib/Unicode; GPL/AGPL запрещены.
- Запрещены зависимости без поддержки (последний коммит > 2 лет) — кроме
  зафиксированных ADR.
- Дублирование функциональности (два HTTP-клиента, две крипто-либы) запрещено.
- `cargo-deny` проверяет advisories, licenses, bans, sources.

## 11. Размер и структура

- Файл — до 500 строк (мягкий лимит), функция — до 60 строк (мягкий).
- Один модуль = одна ответственность.
- Глубина вложенности — до 4 уровней; иначе early-return/декомпозиция.
- `mod.rs` запрещён; используем `foo.rs` + `foo/`.

## 12. Логи и приватность

- Только `tracing`, без `println!` в библиотеках.
- Уровни: `error` — сбой операции, `warn` — деградация, `info` — жизненный цикл,
  `debug` — диагностика, `trace` — только для локальной отладки.
- Запрещено логировать: пароли, ключи, UUID клиентов, полные IP (маскировать),
  содержимое пакетов.
- Каждое сообщение — с полями (`profile_id`, `outbound`, `error.kind`), а не
  склейкой строк.

## 13. Комментарии и TODO

- Комментарий объясняет **почему**, а не «что».
- `TODO` формат: `// TODO(<owner>, #<issue>): <что сделать>`.
- `FIXME` запрещён в `main`; допускается только с issue и сроком.

## 14. Serde и форматы

- Все внешние форматы версионируются (`schema_version`).
- Неизвестные поля в конфигах: отклоняются (`deny_unknown_fields`) для пресетов,
  игнорируются — только для внешних подписок (совместимость).
- Enum-теги — `snake_case`, стабильные строки; переименование = breaking change.
- Даты/время — UTC, RFC 3339.

## 15. Производительность

- Аллокации в горячем пути (обработка пакета) минимизируются; буферы переиспользуются.
- Правила роутинга компилируются один раз при подключении.
- Любая оптимизация подтверждается бенчмарком (критерий: ≥10% улучшения или
  устранение регрессии).

## 16. Definition of Done

Любое изменение обязано пройти [чек-лист готовности](13-definition-of-done.md).
