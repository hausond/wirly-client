# Устав проекта

Статус: **действует**. Изменения — только через PR с ревью владельца продукта.

## 1. Что мы делаем

**hausond vpn** — нативный VPN-клиент для Windows на Rust, который:

- поддерживает современные протоколы (WireGuard, AmneziaWG, Shadowsocks-2022,
  Trojan, VLESS/REALITY, Hysteria2, TUIC);
- даёт управляемый роутинг с готовыми пресетами и правилами по домену/IP/порту/процессу;
- не требует сторонних рантаймов и sidecar-процессов на Go;
- остаётся понятным и поддерживаемым через годы.

## 2. Зачем

Существующие клиенты либо закрыты, либо тянут за собой Go-рантайм, либо плохо управляют
маршрутизацией. Нам нужен инструмент, который мы полностью контролируем: от формата правил
до поведения при обрыве связи.

## 3. Рамки первой версии (v1.0)

Входит:

- Windows 10/11 x64;
- привилегированная служба + непривилегированный UI;
- протоколы: WireGuard, Shadowsocks-2022, Trojan, VLESS (WS/TLS);
- движок роутинга с пресетами и импортом share-ссылок;
- DNS fake-IP, защита от утечек, kill switch;
- автообновление и подписанные сборки.

Не входит (и не должно просачиваться в v1):

- macOS, Linux, мобильные платформы;
- собственный VPN-сервер и панель управления;
- биллинг, подписки, монетизация;
- поддержка протоколов, требующих Chromium net stack (NaiveProxy);
- обход конкретных государственных блокировок как заявленная функция
  (клиент — нейтральный сетевой инструмент).

## 4. Метрики успеха

| Метрика | Цель v1.0 |
|---|---|
| Успешных подключений с первой попытки | ≥ 99% |
| Время от нажатия «Подключиться» до готовности | ≤ 3 с (медиана) |
| Падений на 1000 сессий | ≤ 1 |
| Покрытие строк в `crates/**` | 100% |
| Критические CVE в зависимостях | 0 на релизе |
| Время реакции на security-репорт | ≤ 72 ч |

## 5. Ограничения

- Только Rust для основного кода (UI — Slint). Никаких Go/Rust-миксов в рантайме.
- Лицензия проекта: MIT OR Apache-2.0. GPL/AGPL-код не допускается
  (включая портирование из sing-box/mihomo).
- Поддерживаемая MSRV фиксируется в `Cargo.toml` и проверяется в CI.
- Windows — единственная целевая ОС v1.

## 7. Ключевые риски

| Риск | Влияние | Митигация |
|---|---|---|
| REALITY/uTLS сложнее, чем кажется | срыв сроков фазы 3 | отдельный прототип, ранняя проверка на реальном сервере |
| Несовместимость с чужими реализациями | клиент «не подключается» | interop-тесты против эталонных серверов |
| Привилегированная служба = поверхность атаки | критично | минимальные права, IPC ACL, аудит, fuzz парсеров |
| Утечки трафика при обрыве | критично | kill switch + тесты на утечки |
| Зависимости с несовместимой лицензией | юридические | `cargo-deny` в CI |

## 8. Что считается успехом проекта

Через год проект считается успешным, если:

- v1.0 выпущен и используется владельцем ежедневно;
- новый разработчик (или агент) входит в проект по документации за один день;
- ни один релиз не содержал известных критических дефектов;
- добавление нового протокола не требует правок в ядре туннеля.
