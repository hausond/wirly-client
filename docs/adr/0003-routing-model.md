# ADR 0003: Модель правил роутинга

- Статус: принято
- Дата: 2026-11-06
- Контекст: как описывать маршрутизацию

## Контекст

Нужны переносимые пресеты, читаемые человеком и агентом, с предсказуемым
приоритетом и возможностью расширения без ломки существующих файлов.

## Решение

- Декларативный JSON: `Preset -> Rule[] -> Matcher + Action`.
- Семантика: **первое совпадение выигрывает**, затем `default_action`.
- Матчеры: `domain` (exact/suffix/keyword), `ip` (CIDR), `port`, `process`,
  `network`, `any`.
- Действия: `direct`, `block`, `proxy(name)`.
- Схема версионируется (`schema_version`), неизвестные поля отклоняются.
- Компиляция матчеров один раз при подключении; проверка в `decide` — O(n).

## Последствия

**Плюсы:** простота, тестируемость, детерминизм, лёгкая генерация из UI.

**Минусы:** линейный поиск; при тысячах правил потребуется индексация
(домены — trie/hash, IP — radix tree). Это отдельная оптимизация с бенчмарком.

## Альтернативы

- Clash-подобный YAML: сложнее парсить строго, больше неоднозначностей.
- Код-правила (DSL на Rust): небезопасно для пользовательских пресетов.
